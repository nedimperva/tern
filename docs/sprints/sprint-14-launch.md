## Decisions

- 2026-10-18 — **M2 slice selected by the owner: Linux distribution.** In scope: signed updater for the AppImage
  (and the Windows installer, which comes free), release notes from `CHANGELOG.md`, the AUR `tern-bin` package,
  a pinned toolchain, and ticking the repository files that already landed (f19abdd: README, CONTRIBUTING, SECURITY,
  templates). Deferred: `store_bench` in CI (waits for package 06's failing-bench task), Flatpak and the `tern`
  from-source PKGBUILD (cut first), `THIRD_PARTY.md`, the screenshot, Google/Microsoft verification (with their
  providers), the website, Windows signing (M3).
- 2026-10-18 — **Only the AppImage and Windows builds update themselves.** The updater can also install `.deb` and
  `.rpm` files, but the AUR package is built from the `.deb`, and a `dpkg -i` (or a file swap under pacman) there
  would be wrong. Tern checks only when `APPIMAGE` is set (Linux) or on Windows, and never in debug builds.
- 2026-10-18 — **Releases are no longer marked pre-release.** The updater reads
  `releases/latest/download/latest.json`, which GitHub serves from the newest release that is neither a draft
  nor a pre-release. The draft step stays: nothing reaches installed copies until the owner publishes.
- 2026-10-18 — **No `tauri-plugin-process`.** The update installs from a Rust command that restarts the app itself,
  after the window has saved an open draft, so the extra plugin and its JS permissions aren't needed.
- 2026-10-18 — **Updates are downloaded in the background and installed only on "Restart to update"**, never
  under the person. `requireSignedVersion` is on: a signature must name the version it was made for, so an old
  signed build can't be passed off as a new one. Check: a minute after start, then daily by the wall clock.
- 2026-10-18 — **Signing key** (owner chose: agent generates, agent uploads): generated with `tauri signer
  generate`, kept in `~/.tauri/tern-updater.key` (+ `.password`, `.pub`, all mode 600) on the owner's Omarchy
  machine, and set as the `TAURI_SIGNING_PRIVATE_KEY(_PASSWORD)` repository secrets. **The owner must back up
  `~/.tauri/`**; a lost key means every installed copy needs one manual reinstall.
- 2026-10-18 — `CHANGELOG.md` is written by hand (keep-a-changelog); `git-cliff` isn't adopted, since the
  commit log reads as sprint work rather than release notes. Local `tauri build` makes no updater files (the
  workflow turns them on with `--config`), so building needs no key.

- 2026-10-20 — **Beta readiness slice selected by the owner** (M2 exit gate). In it: a copy of the database before
  each upgrade, a log file and Settings → About, the tester guide (`docs/beta.md`), the M2 acceptance checklist.
  Releases keep Gmail on app passwords (decision record, 2026-10-19), so no consent-screen or verification work.
- 2026-10-20 — **Upgrades keep a copy, not a down-migration.** Migrations only go forward. Before migrating,
  `Store::open` writes `VACUUM INTO mail.db.before-v<old>` (consistent, WAL included) and keeps the two newest;
  the beta guide's "Going back" swaps it in with a table of release → schema. Writing reverse migrations for every
  step would cost more and be riskier than a copy that is known good.
- 2026-10-20 — **The log goes to a file as well as stderr**: `<app log dir>/tern.log` (`tern-dev.log` for debug
  builds), restarted past 5 MB with one `.old` kept, imap-codec's "Rectified" warnings left out. The bug-report
  details name each account's provider only for the big ones ("another IMAP server" otherwise), so a report
  doesn't carry someone's own domain.
