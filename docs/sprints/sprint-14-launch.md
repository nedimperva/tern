# Sprint 14 — Open-source launch

**Status:** todo

**Week 15.** Make it something other people can install, trust and contribute to.

## Goal

A tagged release produces signed, auto-updating builds for Linux and Windows; the repo has the files a
contributor expects; Google OAuth verification is submitted; a short website explains what Tern is.

## Tasks

### CI/CD
- [ ] `check.yml` on every PR: `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test --workspace`, `npm run build`, `store_bench` (fail on regression) on `ubuntu-latest`; `cargo test` on `windows-latest`.
- [ ] `release.yml` on `v*` tags: build on Ubuntu 22.04 (for glibc compatibility) and Windows; produce AppImage, `.deb`, `.rpm`, MSI, NSIS; generate `latest.json` for the updater; upload to a GitHub Release with changelog from `CHANGELOG.md` (keep-a-changelog format, `git-cliff` to draft).
- [ ] Tauri updater: generate the signing keypair (`tauri signer generate`), private key in GitHub secrets, public key in `tauri.conf.json`; `tauri-plugin-updater` + `tauri-plugin-process` with a "Restart to update" toast. Update check on launch and daily.
- [ ] Reproducible-ish builds: `Cargo.lock` and `package-lock.json` committed (already); `rust-toolchain.toml` pinned.

### Packaging
- [ ] AUR: `tern-bin` PKGBUILD from the `.deb`/AppImage, and a `tern` PKGBUILD building from source; publish under the owner's AUR account. Omarchy users install with `yay -S tern-bin`.
- [ ] Flatpak manifest drafted (backlog to publish on Flathub; Tauri + WebKitGTK is well-trodden).
- [ ] Windows: unsigned for now; document SmartScreen; evaluate Azure Trusted Signing / SignPath for OSS later.

### Repository
- [ ] `README.md` rewrite: screenshot, one-paragraph pitch, install per platform, keyboard sheet, "How it works" (local-first), contributing link.
- [ ] `CONTRIBUTING.md`: dev setup, how to run against the fake mailbox, test accounts, sprint process, commit style.
- [ ] `CODE_OF_CONDUCT.md`, `SECURITY.md` (how to report, what we store, keyring note), `CHANGELOG.md`.
- [ ] Issue templates (bug with sync log instructions, feature), PR template with "how to test".
- [ ] `docs/` becomes the project's docs; `CLAUDE.md` stays for agent sessions and links here.
- [ ] License headers not needed (MIT); `LICENSE` + `THIRD_PARTY.md` generated by `cargo about` and `license-checker`.

### Google OAuth verification
- [ ] Publish the consent screen from Testing to In production; submit verification with: app homepage, privacy policy URL (a page stating all data stays on the device; the app has no server), the demo video of the OAuth flow, scope justification for `https://mail.google.com/` (IMAP) and/or `gmail.modify` (API).
- [ ] State clearly that Tern stores no Google user data on servers; request the CASA exemption on that basis. Track the thread in an issue; expect 2–8 weeks and follow-up questions.
- [ ] Until verified: README explains the "unverified app" screen and the 100-test-user cap; offer "use your own client ID" in advanced settings as a fallback.

### Microsoft
- [ ] Publisher verification on the Entra app (MPN account) removes the "unverified" banner; document.

### Website
- [ ] One page on GitHub Pages (`docs/site/` or a separate repo): screenshots, download buttons per platform, the keyboard sheet, privacy policy. No tracking.
